1. INTRODUCTION AND EXECUTIVE SUMMARY
--------------------------------------------------------------------------------
CreBot is a self-serve SaaS platform for building Zero-Speculation AI
chatbots from your own knowledge base. Upload your documents, deploy
instantly, and get grounded answers with one unrelenting standard: absolute
precision, no hallucination.

CreBot is private AI infrastructure for teams who refuse hallucination. Every
chatbot is strictly constrained to the knowledge base the business owner
uploads. If the bot doesn't know an answer, it admits its limitation instead
of guessing — this is the core "Zero-Speculation RAG" philosophy.

Trusted by 1,000+ active teams globally.

Company Vision: "Absolute Clarity" — democratizing enterprise intelligence by
turning scattered documentation into a scalable knowledge engine so
organizations can move faster and eliminate data silos.

Status: Currently in a free-access phase. Paid billing/subscription tiers
are planned for a future release (see Section 3).

2. TARGET AUDIENCE / USE CASES
--------------------------------------------------------------------------------
CreBot adapts to any text-based knowledge base. Core use cases:

2.1 SaaS Customer Support
- Instantly answers repetitive questions about pricing, features, and
  troubleshooting using existing docs.
- Capabilities: reduces ticket volume by ~40%, 24/7 instant resolution,
  seamless human handoff, multi-language support.

2.2 Internal Knowledge / Operations
- Lets employees chat directly with the company wiki and internal docs.
- Capabilities: slashes onboarding time, acts as a single source of truth,
  supports department-specific bots, secure access controls.

2.3 E-Commerce FAQs / Sales
- Answers shipping policies, return windows, and product specs instantly.
- Capabilities: pre-sales objection handling, policy clarification, order
  tracking integration, high-intent lead capture.

2.4 API & Developer Docs
- Lets developers ask questions directly against API references.
- Capabilities: code snippet generation, endpoint discovery, error code
  resolution, SDK usage examples.

Other fits: SMBs automating tier-1 support, solopreneurs without dedicated
support staff, agencies managing chat support for multiple clients.

6. KNOWLEDGE BASE MANAGEMENT
--------------------------------------------------------------------------------
6.1 Supported Upload Formats
- Raw text, Markdown files, PDF documents (parsed automatically), Word
  documents.
- URL scraping — planned future feature, not yet available.

6.2 Training Pipeline
1. Upload — securely ingest PDFs, Word docs, or text files; instantly
   parsed and chunked.
2. Vectorize — text is embedded using state-of-the-art embedding models,
   optimized for retrieval latency.
3. Isolate & Store — vectors are committed to a client-isolated index;
   strict role-based access control (RBAC) ensures data never bleeds
   between tenants.
- A progress indicator shows training status; large documents may take
  longer.

6.3 Best Practices for Knowledge Base Content
- Keep information accurate and current — the bot only knows what's
  uploaded.
- Avoid duplicate/near-duplicate content — it crowds out other relevant
  chunks during retrieval.
- Break large documents into focused, topic-scoped files (e.g., separate
  "Shipping," "Returns," "Product FAQ") rather than one giant merged file.
- Retrain after any update so changes take effect in live chat responses.

7. WIDGET DEPLOYMENT
--------------------------------------------------------------------------------
7.1 Getting the Embed Code
- After training, go to the "Embed" tab and copy the provided snippet.
- Supports iframe or JS SDK integration, embeddable on any website,
  internal wiki, or app.
- Fully customizable CSS to match your brand.

7.2 How the Widget Works
- Appears as a floating chat bubble (typically bottom-right).
- Built in vanilla JavaScript — avoids conflicts with the host site's code.
- Isolates its own styling from the host site via Shadow DOM/iframe.
- Fetches bot configuration (name, colors, welcome message) dynamically —
  dashboard changes reflect on the live widget without re-embedding.

8. BRING YOUR OWN API KEY (BYOK)
--------------------------------------------------------------------------------
8.1 Overview
- Default platform rate limit: 10 requests/minute (RPM), shared queue.
- Bringing your own free Groq API key removes this cap — "uncapped."
- Groq API keys are 100% free to generate via Groq's console.

8.2 Direct Inference — Performance
- With BYOK, queries skip CreBot's centralized queue and route directly to
  Groq's Language Processing Units (LPUs).
- Performance: 800+ tokens/second generation speed, <10ms time-to-first-byte.

8.3 Security of BYOK
- API keys are AES-256 encrypted directly on your device before ever
  reaching CreBot's servers.
- Zero-knowledge design — CreBot has no access to your raw key.

9. ACCESS CONTROL AND TEAM COLLABORATION
--------------------------------------------------------------------------------
9.1 Roles
- OWNER: full control over the bot, including sharing/access management.
- EDIT ACCESS: full access to scan knowledge bases, write configs, and edit
  bot parameters.
- VIEW ACCESS: can view the bot, chat with it, and copy the embed code —
  no configuration changes permitted.

9.2 Sharing Bots
- Bots can be shared across a team or department while strictly
  controlling who can change system parameters.
- Useful for distributing bots to non-technical teammates who only need to
  use or demo the bot, versus admins who configure it.

10. USING THE CHATBOT (END-USER EXPERIENCE)
--------------------------------------------------------------------------------
- Visitor clicks the chat bubble to open the interface.
- Visitor types a question; a typing indicator displays while processing.
- Average response time: under 2 seconds (faster with BYOK/direct
  inference).
- Answers are grounded strictly in the uploaded knowledge base — the bot
  cites the source document and will not fabricate information.
- If a question is unrelated or unanswerable from the knowledge base, the
  bot says it doesn't know rather than guessing.
- Works across desktop, tablet, and mobile devices.

11. ANALYTICS AND CHAT LOGS
--------------------------------------------------------------------------------
- "Chat Logs" shows complete conversation histories per bot.
- Owners can see exactly what visitors asked and how the bot responded.
- Helps identify knowledge base gaps — frequent unanswered questions signal
  what content to add next.
- Planned future analytics: sentiment analysis, automatic surfacing of
  "unanswered" questions.

12. SECURITY AND PRIVACY
--------------------------------------------------------------------------------
12.1 Data Isolation
- Row Level Security (RLS) at the database level — even a malformed
  backend query cannot leak another user's data.
- Client-isolated vector index with strict RBAC — a widget key for one bot
  cannot reach another bot's knowledge base or another tenant's data.

12.2 Authentication and PII
- Clerk manages all PII (email, password, sessions) securely.
- CreBot's database stores only a reference to the authenticated user ID.

12.3 Prompt Injection Prevention
- System prompts are rigidly structured; the model is instructed not to
  answer outside the provided context and to ignore attempts to override
  prior instructions.
- Note: no LLM-based system guarantees 100% prevention of prompt injection
  — this is a mitigation, not an absolute guarantee.

12.4 API Key Security (BYOK)
- User-supplied API keys are AES-256 encrypted client-side before
  transmission; CreBot never has access to the raw key.

13. TROUBLESHOOTING / COMMON ISSUES
--------------------------------------------------------------------------------
13.1 "My bot isn't answering correctly"
- Confirm the relevant info was uploaded and the bot was retrained after
  the last update.
- Vague or thin knowledge base entries lead to weak retrieval — add more
  descriptive context.

13.2 "Training seems stuck"
- Large PDF/Word uploads can take longer to process; wait a few minutes.
- If training fails repeatedly, split the document into smaller files.

13.3 "The widget isn't appearing on my site"
- Confirm the embed snippet was pasted correctly (inside <body>, not
  <head>, for the script-tag method).
- Check the browser console for JS errors or conflicts with other scripts.

13.4 "I've hit my chatbot limit"
- Free plan allows up to 5 chatbots. Delete an unused bot to free up a
  slot, or wait for paid tiers (raising this limit) to launch.

13.5 Rate limit errors ("too many requests")
- Default limit is 10 requests/minute. Wait one minute, or add your own
  Groq API key (BYOK) to remove the cap entirely.

13.6 Slow or failed responses
- If Groq's API is rate-limited or temporarily down, the system retries
  automatically with backoff; a graceful error is shown if all retries fail
  rather than the bot hanging indefinitely.
